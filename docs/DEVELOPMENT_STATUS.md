# Development status

Status checked on 2026-11-01 against the local IAM laboratory working tree, based on `codex/profile-revision-sequence` (itself stacked on the Draft #164 line). This file tracks implementation evidence; `ROADMAP.md` tracks proposed milestones. A Draft PR, green CI, or a catalogue entry does not qualify a production CA.

## Verified implementation boundary

- **CA Core and policy:** Rust `pki-core` and `pki-policy` contain laboratory issuance, policy, approval, serial/idempotency and recovery paths. Their executable tests are under `crates/pki-core/tests`; none of these paths is exposed as an authenticated management write route (`crates/management-api/src/main.rs`, `docs/architecture/management-api-readonly.md`).
- **Management application:** Rust API, migrations `0012`–`0016` and React console provide CA, certificate, audit and immutable profile-*draft* reads. API reads require an OIDC token and a server-owned CA reader grant. The draft catalogue has no activation or issuance effect (`docs/architecture/ca-profile-lifecycle-boundary.md`).
- **Crypto agility:** `crates/pki-crypto/src/suite_registry.rs` has feature-gated laboratory implementation routes for RSA-PSS and RSA PKCS#1 v1.5 (2048/3072/4096/8192 with SHA-256/384/512), ECDSA P-256/384/521 and Ed25519/Ed448. `typed_algorithm_catalog.rs` lists these as *planned* candidates, with none production-qualified. `algorithm_catalog.rs` marks the legacy P-256 and RSA-PSS SHA-256 entries LabOnly and ML-DSA-65 NotImplemented. A registered route or provider advertisement is not evidence of successful issuance or interoperable X.509 for every tuple. ML-KEM is key establishment, not a certificate signature scheme; PQC/hybrid issuance is not implemented.
- **Infrastructure:** Compose, PostgreSQL migrations, CI and test fixtures exercise a disposable lab. The original fixture stack auto-approves sign-in. A separate Keycloak laboratory now verifies real operator and workload identity, but its loopback HTTP and the management database `NoTls` connection (`crates/management-api/src/main.rs`) do not meet a network-facing production boundary.

## Remediation and validation in this branch

- OpenAPI now describes `q`, `policy_version`, `from`, `until`, `min_validity_days`, `min_dns_sans` and cursor filter preservation for profile drafts.
- A Node contract test checks that documented query names equal the Rust query struct and both console page requests. It runs in the existing frontend CI test glob.
- The console validates profile search and policy version by Unicode character count, and rejects interior Unicode control characters after trimming Unicode whitespace, matching the Rust API and PostgreSQL limits. The laboratory smoke now exercises all six profile-draft filters and representative invalid values against the running API and PostgreSQL, including the 128/129-character policy-version boundary.
- The audit console now validates exact event type, decision and policy version by UTF-8 bytes and rejects interior Unicode controls. OpenAPI specifies the 24-character UTC timestamp form and byte limits. The smoke test confirms matching API behavior.
- CA, CN and profile prefix searches now use the same Unicode-aware console validator as the API's shared `literal_prefix` route check. The smoke exercises valid Unicode and rejected short/control values for both CA and CN queries.
- Profile proposal response validation now accepts Unicode text up to the schema's character limits. PostgreSQL verified `length(repeat('😀',128)) = 128` while its UTF-8 size is 512 bytes; the console boundary regression covers all three affected fields.
- The API now requires an approved OIDC `azp` and ties `trust-ca-reader` to the human console client and `trust-ca-workload-reader` to a distinct application client. Unknown clients, either client presenting only the other client's role, and mixed-role tokens are denied. The isolated Keycloak lab now authenticates distinct maker/checker subjects and issues a separate workload credential. The original fixture remains automatic and untrusted for real operator identity. Approval decisions are still absent from the API.
- Migration `0017` rejects gapped existing profile draft histories and locks the CA row while checking a statement's new revisions; it permits contiguous bulk inserts and leaves drafts inert. The read-only API role still has no insert privilege. Fresh install, concurrent inserts, gap-upgrade rollback and migration-ledger apply/retry passed on separate disposable PostgreSQL databases. The local Compose database was upgraded in place after validation: its three draft rows and revision sum of four were unchanged, and the read-only smoke still passed. No management write route or approval state was introduced.
