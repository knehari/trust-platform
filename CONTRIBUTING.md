# Contributing

- No employer-confidential information, proprietary code or internal infrastructure data.
- Use feature branches and pull requests. Require review for security-sensitive changes.
- Link Jira TRUST issue, affected ADR/requirement and tests in every PR.
- Prefer small changes, reproducible tests, dependency locking and documented threat impact.
- No private keys, passwords, tokens or production customer data in commits.
- No claim of audit/certification without independent evidence.
